# Changelog

## 1.1.0 (2026-10-18)
- New synced `agents-review` block in `AGENTS.md` (after `agents-core`): "Review guidelines" with P1 blocking criteria and extra checks, read by AI reviewers and people. `sync.mjs` inserts the block into existing `AGENTS.md` files right after the previous block, leaving all other text unchanged.
- CI-4 rewritten from a PR-review benchmark: Codex GitHub app is the primary reviewer; the Claude review workflow covers every non-draft human PR with no skippable triage step, plus on-demand `@claude`; both read the Review guidelines; no self-hosted Codex workflow; Cursor Bugbot off by default.
- Dependabot: every ecosystem now groups minor and patch updates (`groups: minor-and-patch`) and ignores major updates (`ignore` with `version-update:semver-major`). Majors are done deliberately with the dependency-update skill (new rule SUP-5).
  - Security updates and the major ignore: GitHub's reference marks `ignore` as an option that also changes security-update pull requests, and says ignored dependencies/versions are filtered out of both version and security updates, with no carve-out for security (unlike `allow` `update-types` and `cooldown`, which are documented as version-updates-only). So a security fix that requires a major bump may NOT get an automatic Dependabot PR under this config. This was read from the docs source, not tested against a live advisory. Backstop: the CI-3 dependency audit (high severity fails) still flags it; handle it by hand. Sources: https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference (see `ignore`, and the note that shield-marked options also affect security updates) and https://docs.github.com/en/code-security/how-tos/secure-your-supply-chain/manage-your-dependency-security/controlling-dependencies-updated.
- Wording fix: the moving major line `v1` is a branch, not a tag (cloud sessions get 403 pushing tags). Exact `vX.Y.Z` tags are unchanged.
