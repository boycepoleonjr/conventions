# AI attribution scrub and check (v1.9.0, CI-7)

Status: written while the change was built, so it records the decisions as they were made. The handoff (`docs/handoffs/2026-11-14-ai-attribution-scrub.md`) has what was verified and what was not.

## Problem

Cloud coding sessions append AI attribution to what they write, and there is no setting that turns it off everywhere:

- PR descriptions, comments and reviews end with `🤖 Generated with [Claude Code](...)`, sometimes after a `---` separator, with `Co-Authored-By: Claude ...` lines and a `claude.ai/code/session_...` link.
- Commits get `Co-Authored-By` and `Claude-Session` trailers, or a bot author.

The rule "No AI attribution in commits, PR bodies or comments" (`AGENTS.md`) cannot stop text the platform adds after the agent has finished. So a human or an agent has to clean it up by hand, in every repo, every time.

## Goals

- Text: remove a trailing AI footer from PR and issue descriptions, comments and reviews, automatically, in every synced repo.
- Commits: fail a PR loudly when a commit carries AI authorship, and say how to fix it.
- Ship both as synced workflows with least-privilege permissions and SHA-pinned actions.

## Non-goals

- Rewriting or force-pushing commits. A workflow cannot safely rewrite history, which is why commits get a check and not a scrub.
- Removing AI mentions anywhere but the end of a body. Text in the middle of a body is never touched.
- Blocking AI-assisted work as such, or looking at file contents. Only authorship metadata and trailers.
- Changing `sync.mjs`. Existing repos get the two files as `CREATE` on their next sync.

## Design

### Scrub (`templates/ai-attribution-scrub.yml`, manifest id `ai-attribution-scrub`, job `scrub`)

- **Triggers:** `pull_request` (opened, edited, reopened), `issue_comment` (created, edited), `pull_request_review_comment` (created, edited), `pull_request_review` (submitted, edited), `issues` (opened, edited). One workflow, one job.
- **What it removes, from the end of the body only:** a trailing `Generated by/with Claude Code` line (link or plain, robot emoji or not); the `---` separator and blank lines directly above a removed footer; trailing `Co-Authored-By:` lines naming Claude, Anthropic or noreply@anthropic.com; a trailing `claude.ai/code/session_...` link line, bare or after `Claude-Session:`. Walking up from the last line, it stops at the first line that is none of these, so a footer with anything after it, and a `---` that does not sit in front of a footer, are left alone.
- **Editing boundary:** the cut is made on offsets in the original string, so the text before the cut is returned byte for byte, including Windows and mixed line endings. A body with no footer is not edited (the function returns the same string and the job makes no write call).
- **Fresh read:** the job re-reads the body right before editing and does not trust the event payload. A PR opened and then edited a second later would otherwise have its newer description overwritten with the older one. A small window between that read and the write remains.
- **API calls:** `pulls.update`, `issues.update`, `issues.updateComment`, `pulls.updateReviewComment`, `pulls.updateReview`, each preceded by the matching get.
- **No loop:** edits made with `GITHUB_TOKEN` do not start new workflow runs.
- **Permissions:** workflow default `contents: read`; job `scrub` has `contents: read`, `issues: write`, `pull-requests: write`. No checkout, no secrets, no `pull_request_target`, and no GitHub expression interpolated into the script.
- **Failure behavior:** a fork PR (the token is read-only) is skipped with a notice before any API call, exit 0. A 403 on the edit (Dependabot's read-only token) is a notice, exit 0. Any other error fails the job, so a broken scrub is visible.

### Check (`templates/ai-attribution-check.yml`, manifest id `ai-attribution-check`, job `AI attribution check`)

- **Triggers:** `pull_request` (opened, synchronize, reopened). A separate file, not a second job in the scrub workflow: the scrub also runs on `pull_request` `edited`, and a required check whose job is skipped on some events can report "skipped" (which counts as passing) on the same commit after a real failure.
- **Rules:** a commit is bad when its author or committer email is `noreply@anthropic.com`, its author name is `Claude`, its message has a `Co-Authored-By` trailer naming Claude or Anthropic, or its message has a `Claude-Session` trailer. Only trailers count: the message is read the way `git interpret-trailers` reads it, so a trailer is a line of the final paragraph (after the title paragraph) where every line is a `Key: value` trailer or an indented continuation of one. A `Co-Authored-By: Claude ...` line quoted in prose, in a code block, or in a paragraph followed by more text is not attribution (Codex review, P2). Dependabot commits and merge commits made by GitHub (several parents, committed by GitHub) are ignored. A local merge by an AI author is still flagged, and a one-parent commit made by GitHub (squash, web edit) is still checked.
- **Failure behavior:** one `::error::` per bad commit with its full SHA, subject and reasons, then a failed job whose message names every bad SHA and says how to fix it: re-push the same changes on a new branch with commits authored by the repo owner (no force push needed), with the git commands. If the API returns fewer commits than the PR has (it caps at 250), the job fails: unchecked is not a pass.
- **Permissions:** `contents: read`, `pull-requests: read`. No checkout of PR code, no write scopes, no secrets.
- **Required check:** repos can make `AI attribution check` a required check (STANDARD SET-1, README), after the sync PR that adds the workflow has merged.

### Shared code

`scripts/ai-attribution.mjs` holds the two pure functions, `scrubBody` and `commitProblems`. Synced repos do not have that file, so each function is copied verbatim into its template between `BEGIN`/`END` markers, and a test fails if a copy differs. This keeps `sync.mjs` unchanged. `actions/github-script` v9.0.0 is pinned by full SHA (`3a2844b7e9c422d3c10d287c895573f7108da1b3`); refs are repo-owned after the first sync (SUP-7).

## v1.9.1 (2026-11-15): changes after rollout findings

Codex raised these during the 1.9.0 rollout; each is a patch to the design above.

- **Deny by default.** The three workflows (`ai-attribution-scrub.yml`, `ai-attribution-check.yml`, `conventions-sync-check.yml`) use `permissions: {}` at the workflow level and grant scopes on the job: scrub `contents: read`, `issues: write`, `pull-requests: write`; check `contents: read`, `pull-requests: read`; sync check `contents: read`. Effective permissions do not change today, but a job added later starts with nothing. `claude-code-review.yml` already does this and is not touched (editing it would make the sync PR a self-edit PR that needs a review waiver). `conventions-check.yml` and `deploy-secrets-lint.yml` have the same top-level pattern and are left for a later release.
- **Vendor-independent identities.** The check was Claude-only, but the agents that write PR text and commits are several. `AI_AGENTS` in `scripts/ai-attribution.mjs` is the one list: per tool a label, names or logins (whole, case-insensitive, `[bot]` ignored), exact emails, email suffixes, trailer words and footer names. It is copied into both templates (a drift test) and drives the author and committer checks, the `Co-Authored-By` trailer check and the scrub's footer and co-author lines. Tools: Claude, Codex, Cursor Agent, Copilot, Jules, Gemini. `ignore` lists Dependabot and `github-actions[bot]`; GitHub merge commits are ignored as before. `Claude-Session` stays a trailer key in the list.
- **Scrub footers for the other tools**, end-anchored exactly like Claude Code's. `Co-Authored-By` lines naming a listed agent are removed too, so the scrub and the check agree on what counts as AI attribution.
- **Footer-only body.** If cleaning would leave an empty body, send no edit: log a notice, job green.
- **No personal data in diagnostics.** Reasons name the role and the tool only (`author email belongs to Codex`), never the email, name or login that matched: with the `@openai.com` suffix rule, that value can be a person's own address, and `core.error` writes to Actions logs and annotations (AGENTS.md: no personal data in logs). The log and annotation name a bad commit by its short SHA and no longer print its subject. This supersedes the full-SHA-and-subject annotation described under "Check" for 1.9.0.
- **Accepted trade-offs.** `@openai.com` is matched as a suffix, so a person with an OpenAI address is flagged. Names like `Jules` match only as a whole author name, so `Jules Verne` is not flagged. The identities are taken from the tools' documented bot accounts and from the list the owner gave; a new tool is one entry in `AI_AGENTS` plus a re-copy.
- **Tests.** Every identity as author and committer, by login and by email; trailers per tool; look-alikes; the ignore rules; the list driving both functions (an entry added at runtime is picked up); footer variants per tool; end-anchoring; footer-only bodies for all five events; the permission shape of all three templates.

## v1.9.2 (2026-11-15): output hygiene across the synced workflows

Found while fixing the attribution check's output (v1.9.1, Codex P1: no personal data in logs): the same rule applies to every synced workflow, and two of them still broke it or lacked deny-by-default permissions.

- **Waiver and lookup output.** The self-edit waiver path in `claude-code-review.yml` wrote the admin's GitHub login into an Actions warning (`<login> waived it for <sha>`), and the permission-lookup error wrote the commenter's login and the repo name. The messages are now `Waiver accepted from a repo admin for <short sha>` and `Could not verify the commenter's permission`. The decision logic is untouched. The lookup's stderr is hidden, because the CLI's own error text can repeat the request path, which holds the login. Trade-off: a failed lookup shows no HTTP status.
- **Scan.** Every template was scanned for echoes, annotations and `core.*` calls that print a login, name or email. The attribution check's failure text named the repo owner's login; it now says "the repo owner". A test scans all workflow templates for this from now on.
- **Deny by default for the rest.** `conventions-check.yml` and `deploy-secrets-lint.yml` use `permissions: {}` at the workflow level and `contents: read` on the job. Every synced workflow now follows the v1.9.1 pattern, and a test lists them all, so a new workflow template cannot skip it.
- **Tests.** The real verify step run against a fake CLI that fails like the real one (error text with the request path) through every waiver and lookup path; the scan above; permissions for all six templates.
- **Rollout.** `claude-code-review.yml` changes, so each repo's sync PR is a self-edit PR that needs one `review-waiver`, as for every release.

## Acceptance criteria

1. A body ending in a footer (with or without separator, emoji, link, co-author lines, session link, Windows line endings) is cleaned; a mention anywhere but the end, and a body with nothing to remove, come back identical.
2. Each of the five event types updates the right object with the right API call, only when something changed, and never from a stale payload.
3. A fork PR and a 403 end with a notice and exit 0; any other error fails.
4. The check fails, naming each bad SHA and the fix, for every rule; it passes clean PRs, Dependabot and GitHub merge commits, and commits that only quote attribution lines in prose; it fails on a truncated commit list.
5. Both workflows pin actions by full SHA with a version comment and grant only the permissions above.
6. A new repo gets both files from `sync.mjs --init`, and `--check` is clean. Prettier is clean on both rendered files.

## Rollout

- Release 1.9.0. Synced repos get both files as `CREATE` on their next sync, with no `CONFLICT`. Opt out with the file ids in `skip`.
- The check becomes required in a repo only after its sync PR has merged. A repo whose open PRs already carry AI-authored commits will see the check fail on its next push; the message gives the fix, and the repo can skip the check until it is ready.
- Until a repo has synced, footers there are still removed by hand.

## Risks

- **The scrub edits user-visible text.** Mitigations: end-of-body only, fresh read, no write when unchanged, byte-exact kept text, and tests that run the real script against a fake GitHub. A small race remains between the read and the write.
- **Token permissions on `issue_comment` and review events are untested on GitHub.** The first live run in a synced repo is the real test. A failure is loud (job fails) except 403, which is a notice.
- **False positives in the check:** a human co-author whose name contains "Claude" as a word is flagged (the rule is a word match on Claude or Anthropic); accepted. Commits that only quote the syntax in prose are not flagged, because only the final trailer block is read. Where git is lenient and this check is strict: git also accepts a block that is mostly trailers when it has a recognized one such as `Signed-off-by`, and `(cherry picked from ...)` lines; here every line of the block must be a trailer, so such a block is not read as trailers and a trailer in it would be missed.
- **Duplicated code:** two copies of each function. The drift test makes a mismatch a failing build.

## Test plan

- `test/ai-attribution-scrub.test.mjs`: the pure function, the template contract (SHA pin, permissions, exact triggers), and the real script against a fake GitHub for all five events, a fork PR, a 403, a stale payload and an unchanged body.
- `test/ai-attribution-check.test.mjs`: every rule, both ignore cases, attribution quoted in prose versus real trailers (with a parity test against `git interpret-trailers`), the real script against a fake GitHub for pass, fail naming each SHA and the fix text, and a truncated commit list.
- `sync.mjs --init` then `--check` on a fresh repo, and Prettier 3 on the rendered workflows (the existing `test.yml` step).
