## What changed

1. **Deny by default.** `ai-attribution-scrub.yml`, `ai-attribution-check.yml` and `conventions-sync-check.yml` have `permissions: {}` at the workflow level and per-job scopes (scrub: contents read, issues write, pull-requests write; check: contents read, pull-requests read; sync check: contents read). A new test file, `test/workflow-permissions.test.mjs`, checks all three: one workflow-level key, empty; every job has its own block with exactly those scopes; nothing above `jobs:` grants anything.
2. **Any AI agent.** One list, `AI_AGENTS`, in `scripts/ai-attribution.mjs`, copied into both templates between `BEGIN aiAgents` and `END aiAgents` (drift tests). It covers Claude, Codex, Cursor Agent, Copilot, Jules and Gemini by name, login, email and email suffix. The check uses it for author and committer and for `Co-Authored-By` trailers; the scrub uses it for footer tool names and for co-author lines. Dependabot and `github-actions[bot]` are ignored, with GitHub merge commits.
3. **Footer-only body.** The scrub logs a notice and sends no edit when removing the footer would leave nothing.
4. VERSION 1.9.1, CHANGELOG `## 1.9.1 (2026-11-15)`, spec section, README and STANDARD CI-7 wording.

## Decisions I made that you should check

- **`@openai.com` is a suffix.** You wrote `*@openai.com bot identities`. I matched the whole domain, so a person committing from an OpenAI address would be flagged. If you want only bot-like local parts, change `emailSuffixes` for Codex to exact `emails` and re-copy.
- **`Co-Authored-By` lines in the scrub.** You asked for `Generated by/with` footers for the other tools. I also made the scrub remove trailing `Co-Authored-By` lines naming any listed agent, so the scrub and the check agree. It is still end-anchored.
- **Committer name and login are checked** as well as the author's. 1.9.0 checked the committer email but only the author name.
- **Reason text changed**, for example `author email is codex@openai.com (Codex)`.
- **`Jules` and `Gemini`.** `Jules` matches only as a whole author name (so `Jules Verne` is not flagged), plus the `google-labs-jules` bot. Gemini is in the check list (`gemini-code-assist`), but has no footer entry because you did not list it.
- **Identities I could not verify live.** I took them from your list and from the bot accounts seen on this repo (`chatgpt-codex-connector[bot]`). The Copilot, Jules and Gemini noreply email suffixes are the documented `<id>+<login>@users.noreply.github.com` form. A wrong or missing entry is a one-line change in `AI_AGENTS`.
- **Other templates.** `conventions-check.yml` and `deploy-secrets-lint.yml` have the same workflow-level `contents: read` and are not changed. `claude-code-review.yml` already uses `permissions: {}`. I left the first two out because you only named the sync check; say if you want them in a follow-up.
